## Tatsächliche Produktlücken

1. Studio veröffentlicht den Branch, bietet aber keinen direkten GitHub-PR-Erstellweg.
   Der Agent musste den Draft-PR außerhalb Studio anlegen. Deshalb kein vollständig
   selbstbedienbarer Studio-zu-PR-Ablauf für einen normalen Benutzer nachgewiesen.
2. GitHub Actions im Pilot nicht eingerichtet; PR-bezogene Workflow-Abfrage liefert
   keine Runs. Lokale Studio-Tests sind keine GitHub-CI und keine Branch Protection.
3. Lokale Freigabe für Codex und Push benötigt derzeit Konfigurationsänderung und
   Runner-Neustart. Die UI erklärt dies, führt den Nutzer aber nicht durch die Freigabe.
   Freigaben bleiben nach diesem Test absichtlich wieder geschlossen.
4. Lokaler Prüfstand und veröffentlichter Stand desselben Commits erscheinen als zwei
   getrennte Einträge. Diese Unterscheidung ist technisch nachvollziehbar, aber braucht
   eine klarere Anzeige für den Nutzer.

Unabhängige Freigabe weiterhin offen; keine Selbstfreigabe simuliert. Echte parallele
Zusammenarbeit, Markus-Mac und weitere Anbieter waren nicht Gegenstand dieses Laufs.

## Automationsprobleme

Testdetails sind eingeklappt. Zunächst mehrdeutiger beziehungsweise unsichtbarer
pre-Locator; danach den sichtbaren Schalter Testausgabe ansehen geöffnet und echte
Ausgabe kontrolliert. Keine zusätzlichen Testjobs durch diese Locatorfehler.
Branch-Publikation öffnet kein Ergebnisdialog; zuerst auf falsches Modal gewartet,
danach fertigen Eintrag und Remote-Commit unabhängig kontrolliert. Push war erfolgreich.
Ein Import des Runner-Moduls im REPL scheiterte wegen nicht vorhandenem process-Global;
Negativproben danach unter echter vorhandener Node-Runtime ausgeführt.

Lokale ignorierte Belege: .studio/p3-pilot/full-flow/ (Screenshots und bereinigtes result.json).
Nächster funktionaler Schritt: direkten PR-Übergang und eindeutige Freigabeführung umsetzen;
CI separat begrenzt einrichten. Dafür keine wiederholte allgemeine Bestandsaufnahme nötig.
